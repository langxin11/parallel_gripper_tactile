# 触觉读数与坐标系约定

## taxel

默认 taxel 版本在每个指尖放置 3×3 个球形接触 geom。每个 taxel 都有一个与之对齐的
site 和一个 MuJoCo `force` sensor；左右指尖还各有一个 `pad_force` 与 `pad_torque`。

`view_taxels.py` 显示的是每个 taxel **site 的局部坐标系**，不是世界坐标系，也不是夹爪根部坐标系：

- 红、绿、蓝轴分别为 site 的 +X、+Y、+Z。
- site 跟随相应指尖运动。
- 所有 taxel 的力都以各自 site 的局部轴表示；左右手指不能不经旋转就逐分量比较或相加。

## 为什么压缩时 `Fz` 为负

当前 site 的 +Z 指向指尖表面外侧。taxel 是 pad 的子 body，而 MuJoCo `force` sensor
报告的是**子 body 施加给父 body**的相互作用力，且表达在 site 局部坐标系中。

所以物体压向指尖时，taxel 对 pad 的反作用沿表面内侧，即局部 −Z，原始读数通常满足
`Fz < 0`。如果将压力定义为“压缩越大数值越大”，应使用：

```text
pressure = max(0, -Fz)
```

这不是坐标系设置错误，而是传感器的力作用对象与“物体施加给传感器的力”恰好相反。
若需要后者，可对传感器向量整体取负。

本项目保留原始读取函数用于检查上述 MuJoCo 语义；终端、CSV 和绘图则统一使用整体取反后的
“物体施加给 taxel 表面”的向量，因此对外记录中的压缩 `Fz` 为正，与 touch-grid 一致。

`pad_force` 与单个 taxel 力的物理含义不同：前者用于 pad body 的力/力矩测量，后者只表示
该 taxel 子 body 和其父 pad 的相互作用。不要把九个 taxel 合力当作 pad 的完整外力。

## touch_grid

`touch_grid` 是 MuJoCo 触觉插件，不是离散球形 taxel。每个网格位置提供三通道接触力；插件的
原始通道顺序是 `(fz, fx, fy)`，演示脚本将其整理为局部 `(fx, fy, fz)`。在当前 pad/site 方向下，
`fz` 为正表示正法向压力；终端输出、CSV 和颜色映射都使用其原始 N 值，不做归一化。

其局部坐标系同样由触觉 site 决定。对左右指尖求和后得到的三维力，仍分别处于左右各自的
局部坐标系。若要得到世界坐标系的合力，应使用每个 site 的姿态将向量旋转到世界系后再相加。

### FOV 与 site 位置

`touch_grid` 将接触点相对 site 的方向投影到球坐标网格；FOV 是两个方向的**半角**，落在 FOV
之外的接触不会出现在传感器输出中。因此 site 不能放在 pad 表面附近。当前模型遵循参考实现：
site 位于接触面后 `42.6 mm`。参考项目使用 `fov="14 23"`；当前模型按精确 pad 边界所需的
`14.48 × 23.75°` 转换到本项目 site 轴顺序并向外取整为 `fov="24 15"`，确保长边和短边的
边缘接触都进入网格。修改 pad 尺寸、site 位置、姿态或 FOV 后，必须一起重新校验覆盖范围；
否则总力会被低估，即使物理接触本身正确。

参考项目还对观测量施加 `sign(x) * log(1 + abs(x))`，用于学习输入的动态范围压缩。这里的演示与
CSV 刻意保留未压缩的牛顿值；若用于策略训练，应在观测包装层显式加入该变换，而不是改变传感器或日志。

## 接触模型边界

离散 taxel 的软接触参数可调节接触力的上升速度和数值稳定性，但不模拟硅胶横向扩散、压痕或真实材料形变。
研究这些效应时，应考虑 MuJoCo flex、有限元/降阶软体模型或 `touch_grid` 等专门触觉模型。

## 公平比较约定

球形 taxel 会改变指腹厚度、曲率和首次接触位置，因此不能用来校验 touch-grid 的绝对力。公平
基准使用 `2f85_taxels_box.xml` 与 `2f85_touch_grid_3x3.xml`：两者逐单元共享相同位置、尺寸、
摩擦、`solimp`、`solref` 与 `priority`，只改变 force sensor 和 touch-grid 插件两种读出路径。

taxel 演示在记录入口把原始子 body → 父 body 向量整体取反，统一为“物体施加给指腹”的方向，
因此独立 CSV 和比较脚本中的压缩 `Fz` 都为正。控制量仍是 tendon 位置伺服目标，并非牛顿单位的夹持力命令；
比较时必须保持控制轨迹、对象初态、支撑条件和 actuator 力限一致。

切向扰动比较不能直接相加左右 site 的局部 `Fx/Fy`，因为两侧局部轴的世界方向不同。比较脚本先
分别用 `data.site_xmat` 将左右局部力旋转到世界坐标系，再求世界系合力。启用 `--disturbance` 后，
支撑板只在抓稳阶段参与接触；随后关闭其 `contype` 和 `conaffinity`，以免支撑摩擦替夹爪抵抗切向
外力。方块滑移统一定义为相对扰动起点在世界 YZ 切平面内的位移，而不是某一侧 site 局部位移。

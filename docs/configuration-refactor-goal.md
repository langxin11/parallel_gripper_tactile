# Goal：统一配置组合，支持快速实验迭代

状态：已完成（2026-09-11）。本文同时保留目标、验收清单与迁移证据。

## 目标

将 `configs/` 按设备、模型、控制器、估计器、任务、材料、执行方式和研究方案组织，
通过 Hydra 组合生成经过领域校验的有效配置。用户应能通过选择配置组完成常见实验变化，
无需复制整份 profile。研究配置按待回答的问题和预期决策组织，不按共用 runner 或 task 粗略归类。
CLI 可以随设计调整，现有命令形式不构成目录设计约束。

完成后应支持以下工作方式：

- 切换 DM_Gripper 碰撞模型，只选择另一份 `model` 配置。
- 切换 PID、ADRC 或导纳，选择控制器与相容的估计器配置。
- 添加新任务，只新增任务定义及必要的实验组合。
- 添加正式研究，只维护一份目的明确的权威研究定义，由领域 protocol 生成必要的条件矩阵。
- 已完成使命的模型诊断和已有充分负面证据的控制器，不进入后续默认正式矩阵。
- 所有运行入口消费同一组合解析服务生成的冻结领域对象，并保存完整有效配置。

当前参考规范：[项目架构](architecture.md)、[科研配置](research-configuration.md)、
[测试策略](testing.md)。实施时同步更新这些正式规范。

## 范围与约束

本轮包括配置目录、组合解析、领域适配、入口参数、测试与使用文档的迁移。
允许移除旧路径和旧参数，必须提供明确的新旧映射与迁移说明，不要求长期保留兼容别名。

本轮保持控制算法、物理参数、任务曲线、统计口径和既有证据不变。正式研究的条件矩阵允许按研究目的
裁剪，但每项纳入、排除和停止决策必须引用已有证据，并保留历史配置与产物的解释能力。导纳 profile 当前还包含
不同的 MIT 增益、接触阈值和滤波参数，不能只搬走 `admittance` 字段就认定迁移等价。
每项差异必须分配到明确的配置所有者，并在完整组合结果中验证。

Hydra 留在入口与配置编排层；runner、仿真循环、共享控制核和硬件基础包继续消费领域对象。
本轮不新增硬件运行能力，不创建尚不支持的 `hardware.yaml`，不引入新的调参或分布式执行框架。

## 目标目录

以下为目标布局示意，文件名可在第一个迭代中收敛；未列出的现有方案须在迁移清单中覆盖。

```text
configs/
├── README.md                       # 配置入口、所有权与常用组合
├── run.yaml                        # 单次实验组合入口
├── study.yaml                      # 正式研究组合入口
├── platform/
│   ├── dm_gripper/simulation.yaml
│   └── robotiq_2f85/simulation.yaml
├── model/
│   ├── dm_gripper/
│   │   ├── height_spheres.yaml
│   │   ├── flat_spheres.yaml
│   │   ├── coplanar_mesh.yaml
│   │   └── original_mesh.yaml
│   └── robotiq_2f85/                # 现有模型与触觉布局变体
├── controller/
│   ├── dm_gripper/                 # PID、ADRC、导纳等完整控制配置
│   └── robotiq_2f85/
├── estimator/
├── task/
│   ├── force_tracking/
│   ├── force_scheduling/
│   ├── friction_estimation/
│   └── discrete_force/
├── material/
├── execution/                      # 计划、执行与产物选项
├── experiment/
│   ├── dm_gripper/                 # 常用单次实验组合
│   └── robotiq_2f85/
└── research/                       # 每个目录对应一个研究问题与决策
    ├── force_controller_selection/
    ├── force_controller_ablation/
    ├── torque_adrc_tuning/
    ├── stiffness_estimator_validation/
    ├── friction_local_slip_validation/
    ├── dm_admittance_tuning/
    ├── robotiq_discrete_force_validation/
    └── archive/
        └── model_bug_diagnosis/
```

`study.yaml` 是组合入口，`research/<purpose>/` 保存权威研究定义。目录名回答“为什么研究、要做什么
决策”，而不是“使用了哪个 task”。可复用的 Step、Ramp、Mixed 等物理任务继续放在 `task/`；
研究目录只选择回答当前问题所需的任务。研究类型、阶段、参数与矩阵定义应由同一研究配置提供，
消除当前 `research/study/` 对 `studies/` 的纯路径包装。
Hydra 的配置组 package、绝对组路径、defaults 顺序及单次／研究执行配置差异必须用真实组合测试确认。
本文不把目录示意当作可以直接运行的 Hydra 配置。

## 配置所有权

| 配置组 | 负责内容 | 验收重点 |
| --- | --- | --- |
| `platform` | 设备家族、后端、机构、安装、设备能力与边界 | 更换控制器不改变机构或协议限制 |
| `model` | MJCF 资源、碰撞近似及相容的仿真触觉布局 | 模型与 taxel 布局一起校验 |
| `controller` | 控制律、MIT 增益、控制滤波、接近与接触过渡参数 | 导纳、PID、ADRC 切换后没有无关算法字段残留 |
| `estimator` | 刚度估计方法与参数，或显式关闭 | 相容性由领域校验保证 |
| `task` | 目标曲线、时序、扰动与任务验收参数 | 原始任务值与时间语义保持一致 |
| `material` | 接触材料 preset | 不隐式覆盖任务或控制器参数 |
| `execution` | 计划／执行、输出、查看、记录 | 不参与科学条件定义 |
| `experiment` | 常用配置组选择与有意覆盖 | 只组合已有定义，避免复制整套参数 |
| `research` | 研究问题、决策、准入条件、条件轴、配对、seed、阶段与谱系 | protocol 唯一展开必要矩阵，计划与执行共享 `StudyPlan` |

噪声基线、采样周期等跨组字段在迭代 1 中逐项明确所有权，禁止凭目录名字静默改变现有语义。
设备硬限制优先于控制器的可调限制，冲突组合应在运行前报错。

## 正式研究的准入、退出与归档

每个正式研究在配置或同目录说明中明确记录：研究问题、预期决策、比较对象准入条件、任务选择理由、
主要指标、停止条件以及排除证据。不能因为多个研究都调用 `force-track`，就把不相关问题放进同一个
study 或条件矩阵。

- 为定位模型 bug 建立的碰撞几何、求解器或接触语义对照，在问题定位并修复后移入
  `research/archive/model_bug_diagnosis/`。保留配置、结论和产物引用用于追溯，但不进入论文正式对比、
  默认计划或日常回归矩阵。
- 已有稳定证据表明性能明显较差，且继续比较不能回答当前研究问题的控制器，从正式矩阵退出。
  保留独立复现入口及退出依据，不反复消耗完整任务 × 材料 × seed 矩阵。
- `direct-torque`（MIT 直接力矩基线）不进入后续默认控制器性能对比。其历史结果继续用于说明欠阻尼等
  已观察现象；需要复核架构问题时通过独立复现配置运行。
- 正式对比只保留仍有竞争力、代表必要基线或能回答消融问题的方法。调参、消融、模型诊断和最终选型
  分属不同研究目的，分别维护矩阵和验收标准。
- 归档不是删除。历史 manifest、有效配置、Git 提交和结论必须可解释；默认自动化不运行归档研究。

## 迭代清单

按顺序推进，每次交付一个能验收的闭环。完成一项后记录证据，再进入下一项。

- [x] **迭代 1：锁定迁移基线。** 盘点全部 profile、task、Hydra preset、study 与入口引用；
  记录当前 Git 提交、解析后的完整默认值、资源摘要和各研究矩阵。形成字段所有权表与新旧路径映射。
  同时将研究分类为“正式保留、独立复现、诊断归档、淘汰候选”，为每项研究记录目的、决策和证据。
  验收：每个现有配置都有去向，DM 导纳与碰撞变体的全部差异均被解释；模型 bug 对照与低性能控制器
  不会未经评审迁入新的正式矩阵。
- [x] **迭代 2：打通 DM 单次力跟踪。** 实现统一组合服务和目标配置组，迁移默认 DM 运行、
  导纳运行、碰撞变体及估计器切换，输出冻结的 profile／task 等领域对象。
  验收：新旧完整有效参数及资源一致；计划模式可组合和编译场景；不相容组合在运行前失败。
- [x] **迭代 3：覆盖其余单次实验。** 迁移力调度、摩擦估计、Robotiq 离散力以及查看、抓取、
  接触比较和视频入口；复用同一解析服务。
  验收：迁移清单中的单次入口全部有可运行示例；模型变体和任务测试通过。
- [x] **迭代 4：按目的重建研究。** 合并研究包装与权威定义，只迁移仍服务明确决策的正式研究；
  模型 bug 诊断移入归档，低性能控制器转为独立复现，Torque ADRC coarse／confirm 保持独立谱系。
  验收：保留条件的科学参数、配对键、基线角色及失败分类与迁移前一致；删除的条件均有退出依据；
  `direct-torque` 不出现在默认控制器性能对比计划中。
- [x] **迭代 5：收尾。** 更新 CLI、文档、配置索引和 CHANGELOG；清除迁移过渡文件及失效引用。
  验收：全量检查通过，迁移清单闭合，常见实验变化无需复制完整 profile。

## 验收方法

1. 在删除旧配置前，以当前实现生成并保留独立基线。比较时展开领域默认值，比较完整参数与
   资源内容；路径改写采用显式映射，不能只比较少量挑选字段，也不能让期望值来自新组合实现。
2. 覆盖 DM 默认、导纳、碰撞变体，Robotiq 三类现有 profile，以及全部可复用 task。正式研究只验证
   评审后保留的目的与矩阵；独立复现和诊断归档验证其可读取与可解释。对关键控制链路保留现有
   数值／轨迹回归测试；出现差异先定位原因，禁止直接放宽容差。
3. 验证不同工作目录下的组合结果一致、覆盖优先级可解释、未知字段和不相容组件明确报错。
   计划模式不得推进仿真或访问设备，单次与正式研究的计划／执行边界分别验证。
4. 验证有效配置、组合来源、产物登记及恢复检查。路径或序列化变化可能影响历史哈希，必须记录
   原因与兼容策略，不能宣称旧 study 自动兼容。历史实验目录及报告引用按真实产物保留。
5. 开发时运行相关测试；完成重构后执行仓库要求的 Ruff、格式与全量 pytest 门禁。
   全量仿真研究矩阵不必重新执行；保留矩阵必须完成计划等价验证，主动裁剪的矩阵必须验证退出清单。

## 后续维护

后续变更应继续遵守以下约束：

> 新增或修改实验时只维护职责明确的配置片段与必要 experiment；正式矩阵只在对应目的目录维护，
> 由 protocol 唯一展开。运行入口必须消费组合后的冻结对象并保存有效配置；历史矩阵变化须对照冻结基线，
> 记录准入、退出、阶段谱系与哈希兼容策略。
